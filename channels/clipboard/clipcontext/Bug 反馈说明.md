# ClipContext Bug 反馈说明

遇到问题时，请先记下发生时间和界面提示，再按下面的步骤检查。把文末模板发给向你提供安装包的人或项目维护者，即可提交反馈。操作方法可查阅同目录的[使用说明](使用说明.md)。

## 先确认版本和使用环境

- **ClipContext 版本**：打开面板，在卡片的更多菜单中选择「关于 ClipContext」。记录显示的版本号；如果能看到构建号，也一并填写。无法启动时，可在 Finder 中选中应用，按 `⌘I` 查看版本。
- **macOS 与芯片**：打开苹果菜单 →「关于本机」，记录 macOS 版本，以及 Apple Silicon 芯片型号或 Intel。无需提供序列号、设备名称或 Apple 账号。
- **正在使用哪一份应用**：说明是首次安装还是替换升级，是否还同时运行旧版 ClipContext、Maccy 或其他剪贴板工具。
- **界面和输入方式**：说明使用卡片还是列表、界面语言，以及鼠标操作或实际按下的快捷键。若只在某个输入法、显示器或缩放比例下出现，也请写明。

## 常见问题先检查这些

| 现象 | 先检查 |
| --- | --- |
| 复制后历史里没有新内容 | 确认应用正在运行、没有暂停记录或开启「忽略下一次」。检查隐私设置中的忽略应用、内容类型和规则。用一段普通测试文字再试一次。密码管理器标记为机密的内容可能不会记录。 |
| 选中条目后没有自动粘贴 | 默认操作是把内容复制回剪贴板，请先回到目标应用按 `⌘V`。需要直接粘贴时，检查设置中的默认行为，并使用对应的粘贴操作。 |
| 直接粘贴或顺序粘贴无效 | 这两项功能需要 ClipContext 的辅助功能权限。应用提示时可点「打开系统设置」，由你在 macOS 中完成授权；之后重新执行操作或重新开始队列。无需为普通复制、搜索开启无关权限。确认目标应用的可编辑输入框已有光标。 |
| 队列没有按预期继续 | 查看是否已经点「开始顺序粘贴」，以及剩余数量。回到目标输入框，每次实际按一次 `⌘V`。期间复制新内容、另选历史或删除队列条目可能停止队列。记录选择顺序、实际输出顺序和剩余数量。 |
| 搜索、收藏板里找不到内容 | 清除搜索词，检查收藏、收藏板和类型筛选。记录切回全部历史后是否出现，避免直接清空历史来排查。 |
| Agent 看不到资料 | 在设置 → Agent 检查共享方式。共享默认关闭；先手动分享一条合成测试资料，再点「立即同步」，查看写入条数和时间。还需确认 Agent 已正确连接 MCP、对应 CLI 已登录且可使用。同步目录与生成简报是两个步骤。 |
| Google Drive / iCloud 没更新 | 在 Agent 页检查连接、所选目录、上传或同步状态及错误提示。Google Drive 可用「打开副本」核对文件；iCloud 本机目录写入后还要等待 macOS 上传。不要只凭本机文件存在就判断另一台设备已收到。 |
| Google 授权页面报错 | 记录错误文字，以及发生在登录、确认权限还是回到本机的哪一步。重试时从应用重新发起授权。不要提交含授权码或 token 的完整回跳网址。 |

如果以上检查未解决问题，继续提交反馈即可。不要为了排查而删除历史库、清空云端目录或重置全部权限。

## 用最少的资料复现

1. 准备合成内容，例如「测试 A」「测试 B」，或一段写着「测试粗体」的富文本。文件问题可使用无个人信息的空白测试文件。
2. 从明确的起点开始，按顺序记录每次点击和按键。涉及粘贴时，写出复制来源应用与粘贴目标应用，并说明目标输入框是否获得焦点。
3. 在不会丢失资料的前提下重复两三次，记录成功与失败次数。不要只写“偶尔不行”。
4. 截图只保留有关控件、错误提示和测试资料；录屏尽量短，避免录到其他窗口。发送前检查文件内容。

反馈通常不需要真实剪贴板历史。**不要发送完整历史数据库、共享目录中的 `clipboard.json`、完整云盘目录、聊天记录、账号密码、OAuth 客户端密钥、授权码、访问 token 或刷新 token。** 也不要为复现而把共享方式改为「所有历史」。

错误文字可以直接复制；如果附日志，仅保留本次问题对应时间附近的必要片段，并遮去个人路径、账号和机密内容。日志、截图和录屏都是可选项；没有这些材料也可以提交。

## 把反馈交给维护者

有仓库访问权限的用户，可通过 [GitHub Issues](https://github.com/BENZEMA216/ClipContext/issues/new/choose) 选择「Bug 反馈」并填写表单，也可以将上面的模板粘贴到 Issue 中。请保留问题编号；补充复现资料时继续回复同一个问题，方便关联。

没有仓库访问权限的用户，将填写好的 Markdown 反馈交给提供安装包的人，由维护者代为登记。

维护者可能请你使用合成资料再复现，或核对一个具体设置。若需要额外日志，应先说明所需范围；不要直接打包整个应用数据目录发送。
