# Agent 对话历史的本机验收

2026 年 11 月 22 日，在单独的私有 SQLite 库中导入客户端历史、用户已有的账户导出，以及已登录网页能够显示的消息。验收从整理出的项目记忆出发，按证据标识回到了用户原先提出需求和随后调整要求的两条消息。[实现 PR #13](https://github.com/BENZEMA216/context-instrumentality-project/pull/13) · [整理工单 REC-67](https://linear.app/zhiming-app/issue/REC-67)

| 环节 | 已验证的行为 |
| --- | --- |
| 来源与原文 | 13 个来源在真实库中有用户或助手的可见消息。每条 Raw 保留角色、会话、来源标识及可获得的时间。网页未展示原始时间的条目标记为时间未知。 |
| 摘录与项目记忆 | 在本机按消息生成可追溯摘录。对所有活动 Raw 核对正文哈希及与摘录的双向一一对应。6 条另行归纳的项目记忆保留原文证据，同一主题可以引用不同轮次。 |
| 幂等与管理 | 从 5 个来源抽选 11 条消息重导，新增和修改均为 0。本地管理页验证了所有者访问；按会话或项目也可经 CLI 打开原文和摘要。 |
| 真实私库的 Agent 可见性 | 默认所有记录仅本机可见。以原有 30 秒超时的正式客户端查询十万条以上记录，Raw 和 Memory 均在约 0.015 秒返回空集。同一条记录按 ID 读取，所有者成功，Agent 收到 404。[REC-68](https://linear.app/zhiming-app/issue/REC-68) |
| 已放行记录的 Agent 回查 | 单独的合成测试通过实际 MCP 进程放行一条、检索 Memory、按证据回查 Raw，再由所有者删除。删除后两个入口均不再返回该条。 |
| 跨轮回顾 | 用相同 CLI 参数读同一批证据，单场会话摘要耗时从 93.83 秒降至 1.60 秒，跨会话的项目摘要从 94.13 秒降至 2.19 秒。三组命令的前后输出指纹一致。[REC-69](https://linear.app/zhiming-app/issue/REC-69) |

消息摘录、用户提出的变更、助手自报的进展都有来源可查。跨分支讨论中的冲突决定仍需核对原讨论。网页覆盖以该次可见的会话、已渲染正文和分支为限，账户完整性需要与官方导出另行比对。
