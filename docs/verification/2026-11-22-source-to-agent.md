# 录音与剪贴板的 Agent 回查验收

2026-11-22。先核查真机长录音在日常接收链路的状态。另用合成语音和剪贴板测试文本，在隔离 Hub 中让独立 Codex 通过只读工具查找原句，提问不含预期答案，同时核对返回的 Raw ID 和来源定位。

## 录音

**真机长录音。** iPhone 诊断显示已有来自手表的片段持久保存。按录制区间重叠及 Mac 实际入库时间分别核查，本机接收库均为 0；录音 MCP 的同窗查询也为空。日常 Context Hub 的 Raw 和 Memory 均为空，Hub MCP 无原句可查。

**隔离测试。** 输入是一段中文合成语音，参考句为「蓝鲸把周三的会议改到九点。」音频为单声道 16 kHz、41,460 帧，时长 2.59125 秒。同一份音频分别配上人工指定的参考转写和实际本机 ASR 转写，在两个空库验证。

| 环节 | 观察结果 |
| --- | --- |
| 接收与持久化 | 在隔离实例经本机 HTTPS 投递不带转写的 CAF 导出包。两次相同投递均得到 HTTP 200 和同一份持久回执；回执、归档摘要、录音 ID 与实际保存的音频一致。 |
| 本机转写 | 两次从没有既有转写的目录识别同一 CAF，均得到「南京把周三的会议改到 9点。」主体发生变化。本样本只证明这条声音的误识。[REC-65](https://linear.app/zhiming-app/issue/REC-65) |
| Hub 与权限 | 两份带转写的单段导出包各经生产导入器进入独立空库。每份首次新增 1 条，重导新增 0 条。默认仅本机可见时，真实 Codex 查 Memory 和 Raw 都为空，回答未知。 |
| 获准后的 Agent 回查 | 两次盲问均先 `search_memory` 再 `get_raw`。参考转写组逐字找回「蓝鲸把周三的会议改到九点。」，实际 ASR 组逐字找回「南京把周三的会议改到 9点。」两次 Raw ID、片段定位与段内时间均吻合。从 Codex CLI 启动到回答分别为 19.31 秒、20.74 秒。 |

合成测试覆盖 Mac 的接收逻辑、导出包导入和转写回查。真机验收沿用户已有录音核对手表分段、手机持久回执、Mac 接收、Hub 和获准 Agent 的引用。Mac 现有接收服务对连接状态查询返回 HTTP 405，实际投递应查对应片段的持久回执。[同段真机验收 REC-61](https://linear.app/zhiming-app/issue/REC-61) · [接收端状态探针 REC-35](https://linear.app/zhiming-app/issue/REC-35)

## 剪贴板

使用经签名与文件摘要校验的 [ClipContext 0.1.4/build 5 预发行包](https://github.com/BENZEMA216/ClipContext/releases/tag/v0.1.4)。通过发布二进制自带的测试入口指定命名剪贴板与独立持久目录，两次启动同一份原生应用。测试没有接触日常账户的通用剪贴板。

| 环节 | 观察结果 |
| --- | --- |
| 采集与重启 | 普通文本、富文本和再次复制同一内容产生 3 个复制事件。标记为 concealed 的测试项被排除。退出再启动后保留 3 条，复制一个新生成的测试口令后共 4 条。 |
| Hub 导入 | 显式导入应用生成的 Raw manifest，首次新增 4 条，重导 4 条 unchanged。Owner 可见 4 条 Raw、3 条 Memory；排除项在两层均无记录。 |
| 权限与回查 | Agent 默认可见 0 条 Raw 和 0 条 Memory。只放行重启后产生的那条记录后，两层各可见 1 条。独立 Codex 通过一次 `search_memory` 和一次 `get_raw` 逐字找回盲测口令，Raw ID、归档定位均匹配。 |

以重启后那次复制为零点，归档清单在 58.643 秒落盘，Hub 中这条 Memory 在 104.481 秒完成最后一次写入。Agent 成功查询的回执给出上界 104.484 秒，独立 Codex 返回原句并核对出处的回执给出上界 126.693 秒。单次计时包含定时归档、显式导入、授权及一次模型启动重试。

已验证受控复制到 Agent 回查。普通图形会话里通过 macOS 辅助功能权限执行跨 App 自动粘贴，仍在同一工单中待验。[剪贴板验收 REC-62](https://linear.app/zhiming-app/issue/REC-62)
