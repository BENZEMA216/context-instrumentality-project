# Context Hub 首轮验收

2026-11-21。全部样本是合成资料。以下是对运行中服务的观察，可用[入门示例](README.md)重做核心流程。

| 验证层 | 操作 | 观察 |
| --- | --- | --- |
| 正常问答 | 从空工作目录发起真实 Codex 会话，经 stdio MCP 访问 HTTP 服务，询问银杏收音笔第一版的范围 | 完成一次 `search_memory`，回答第一版做日期筛选，第二版做客户分组。原文读取次数为 0 |
| 明确核验 | 用另一独立 Codex 会话要求逐字引用校正标签并给出定位 | 完成一次 `search_memory` 和一次 `get_raw`。正确引用“周三的校正标签为松针蓝七号。”，返回具体记录 ID 和 `fixture://recordings/s01#t=12,20` |
| 管理页 | 真实浏览器从空库创建 Raw、提取 Memory、从 Memory 打开来源，手工选择证据新建记忆，再编辑和删除两类记录 | 详情可回查来源，取消删除有效。模拟第二客户端抢先写入，页面收到 409 且保留草稿。14 条记录按 12 + 2 分页，检索命中正确条目 |
| 页面与显示 | 桌面深浅色、390px 移动布局、含 HTML 标记的来源文本 | 移动端可从列表进入详情并返回，无横向溢出。来源文本以字面值呈现。README 截图使用独立合成库 |
| 导入 | ClipContext 快照与 durable manifest、录音 ZIP 和独立清单、通用事件 | 验证原生结构、来源身份与指纹，已有转写分段可取回。两台设备上相同原生项 ID 保持独立。重复导入同一材料不制造新记录 |
| 隐私与失效 | 将证据降级为 local_only，或修改、删除支持人工记忆的原文 | Agent 立即看不到失效记忆，Owner 可复核待审记录。删除或周期任务不会使旧内容重新出现。经回环隧道向 cloud 导入 local_only，预检只发到 /health，不发送正文或记录 ID |
| 多次重启与并发 | 独立安装 wheel，以测试证书经 HTTPS 代理连接云模式服务，更换服务进程两次 | 两层内容、版本和证据链保留。12 个并发相同导入均读回修订 1。12 个持相同版本的不同修改中，1 个成功，11 个返回 409 |
| 删除落盘 | 删除含特征字符串的合成原文和人工记忆，关闭全部连接，检查 SQLite 行与数据库文件 | 已删正文、搜索列及关联边清空，身份墓碑阻止重导。单次静态文件检查未找到测试标记。备份、系统快照和活跃 WAL 有独立生命周期 |
| 分发 | 在源码目录外以普通 venv 和 pip --target 分别安装构建好的 wheel | 两种安装均能加载事件 Schema 和录音生产者验证代码。独立 MCP 客户端可发现 10 个工具 |

这两次 Codex 调用验证了两条路径确实可用。它们没有测量真实工作负载下的回查概率或摘要准确率。容器构建和 Linux 回归结果见该提交对应的 GitHub Actions「Context Hub」工作流。未部署到公网生产环境。
